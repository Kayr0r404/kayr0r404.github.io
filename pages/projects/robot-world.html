Robot World

A Java 21 application exploring world simulation, persistence, clean code and collaborative software delivery.

The problem

The project needed reliable world persistence while keeping the saved world separate from transient robot state. Database structure, connection management and repeatable builds were important engineering concerns.

What I built

The application uses SQLite for world data and HikariCP for connection pooling. Save/restore operations persist world state rather than robot state. The team also worked with CI pipelines and Docker image publishing.

What I learned

Persistence boundaries should reflect the domain: not every runtime object belongs in durable storage. Clean interfaces and automated build pipelines help teams make changes safely.
