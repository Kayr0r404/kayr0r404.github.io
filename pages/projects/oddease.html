PROJECT CASE STUDY · AUTHENTICATION SERVICE

OddEase

A dedicated authentication service designed to provide identity and token-based access for a wider application.

The problem

As an application grows into multiple services, authentication should be consistent and resource services should not each invent their own identity model. The design explores keeping identity concerns in a dedicated service.

What I built

The current authentication service is built with FastAPI and JWT access/refresh tokens. The architecture direction is to keep authentication in Python while implementing additional resource services in Java, with those services validating tokens and enforcing resource authorization.

My contribution

Designed and implemented the authentication service and explored how Java-based services can validate identity and authorization before exposing protected resources.

Technology

Python · FastAPI · SQLModel · PostgreSQL · MongoDB/Beanie exploration · JWT · Java services (planned integration)

What I learned

Token validation and authorization are related but distinct. Services need explicit trust configuration, issuer/audience checks, expiry handling, key management and resource-level permission checks. Cross-language services benefit from a documented token contract.
