tlik Marketplace

A clothing and home-utilities storefront with a React client and a Flask backend responsible for API workflows, identity and persistence.

Problem and product scope

An online store needs product discovery, account management, cart and wishlist workflows, order handling and a payment boundary that is kept separate from the storefront interface.

Architecture

React storefront · React Router
↓ HTTP / JSON
Flask application · API Blueprint
↓
User · product · cart · order · wishlist endpoints
↓
SQLAlchemy DBStorage / session
↓
MySQL relational database
↔ payment integration
Stripe

The React application is the presentation layer. The Flask server registers a versioned API blueprint, initializes JWT handling and application storage, and exposes resource workflows. SQLAlchemy-backed DBStorage manages relational records; Stripe is integrated as an external payment provider.

Technology and responsibilities

  • Frontend: React, React Router, Axios and Bulma.
  • Backend: Flask 3 with a Blueprint-based API.
  • Identity: Flask-JWT-Extended and Flask-Bcrypt.
  • Persistence: SQLAlchemy and MySQL.
  • Payments: Stripe integration.

Architecture considerations

The API boundary keeps database access and payment-provider calls out of the browser. Important areas to strengthen include request validation, explicit service/repository boundaries, least-privilege CORS settings, idempotent payment handling and reconciliation between local order state and Stripe payment state.
