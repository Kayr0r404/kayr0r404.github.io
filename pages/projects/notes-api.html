Notes API Platform

A React notes client backed by Django REST Framework, with JWT-based authentication and private/public note endpoints.

Problem and product scope

Users need to create, retrieve and manage notes while controlling which notes remain private and which can be viewed publicly. Access control must be enforced by the API, not only by the frontend.

Architecture

React 19 client · React Router
↓ HTTP / JSON
Django 5.1 · Django REST Framework
↓
SimpleJWT · HttpOnly access / refresh cookies
↓
Authenticated note and user views
↓
Django ORM · SQLite (configured database)

The React application handles the user experience and calls the Django API. Django REST Framework provides registration, token, note and public note endpoints. The settings configure both a cookie-aware JWT authentication class and SimpleJWT authentication, with authenticated access as the default permission policy.

Technology and responsibilities

  • Frontend: React 19 and React Router 7.
  • API: Django 5.1.5 and Django REST Framework 3.16.
  • Authentication: SimpleJWT with access/refresh tokens stored in HttpOnly cookies.
  • Persistence: Django ORM with SQLite configured in project settings.

The dependency file includes MySQL and SQLAlchemy packages, but the checked-in Django settings configure SQLite as the active database. This case study describes the configured application rather than assuming a MySQL deployment.

Architecture considerations

The important boundary is between authentication and note authorization. The API should consistently check ownership for private notes and expose public notes through an explicitly public query path. Cookie-based JWT authentication also requires deliberate CSRF, CORS, secure-cookie and token-refresh handling across local and deployed environments.
