RAG Assistant

A Streamlit application that indexes uploaded documents and URLs, retrieves relevant passages from a vector index and uses Gemini to answer questions grounded in that context.

Problem and workflow

A language model does not automatically know the contents of a user's private documents. The application creates a retrieval path that makes document content available to the model at question time.

Architecture

Streamlit UI · upload PDF / provide URL
↓
UniversalPDFLoader · text extraction
↓
Chunking · Gemini embeddings
↓
Pinecone vector index · tenant namespace
↓ query
Top-k vector retrieval · retrieved context
↓
Gemini answer generation

The Streamlit interface calls a GeminiRAG orchestration class. Ingestion extracts document text, splits it into chunks, embeds each chunk with Gemini and upserts vectors into Pinecone under an organization namespace. At query time, the query is embedded, the most relevant chunks are retrieved and their text is passed to Gemini as context.

Technology and responsibilities

  • Interface: Streamlit.
  • Document ingestion: UniversalPDFLoader, PDF/URL loading and text chunking.
  • Embeddings and generation: Google Gemini API.
  • Vector retrieval: Pinecone serverless index with namespace separation.
  • Observability: Langfuse tracing around retrieval and generation operations.
  • Packaging: Docker support.

The repository README labels FastAPI/Inngest and MongoDB Atlas as work in progress. They are not shown as part of the active request path in this case study. The implementation uses Pinecone, not MongoDB Atlas Vector Search.

Architecture considerations

Retrieval quality depends on document parsing, chunk boundaries, embedding consistency, namespace isolation and retrieval relevance. The current implementation uses a simple paragraph-based chunking strategy and top-five vector retrieval; production hardening would add evaluation datasets, source citations, ingestion status tracking, retries and tenant-level access controls around document operations.
