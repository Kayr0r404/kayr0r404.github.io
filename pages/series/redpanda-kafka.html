LEARNING SERIES · IN PROGRESS

Redpanda for application developers

A practical journey from zero knowledge of event streaming to designing, implementing and operating event-driven applications using Redpanda's Kafka-compatible API.

This is a learning roadmap and working set of notes. Sections will be expanded with tested code, diagrams and implementation examples as the work progresses.

PART 1

Why event streaming exists

Understand synchronous request/response, queues, event logs and when asynchronous communication is useful. Learn the difference between a message broker, event stream and traditional task queue.

Concepts · messaging patterns

PART 2

Core architecture

Explore brokers, clusters, topics, partitions, offsets, replication, leaders and consumer groups. Understand how partitioning affects ordering and parallelism.

Architecture · cluster model

PART 3

Producers and consumers

Build Java and Python producers and consumers. Learn serialization, keys, acknowledgements, batching, polling, commits and consumer rebalancing.

Hands-on · client APIs

PART 4

Delivery guarantees and reliability

Study at-most-once, at-least-once and exactly-once semantics, idempotent producers, retries, duplicate processing and dead-letter strategies.

Reliability · failure handling

PART 5

Schemas and data contracts

Introduce JSON, Avro and schema registries, compatibility rules, event versioning and evolution without breaking consumers.

Data contracts · schema evolution

PART 6

Operations and production readiness

Explore security, TLS, SASL, ACLs, monitoring, lag, retention, compaction, backups, capacity and deployment with Docker.

Operations · observability

PART 7

Build a complete project

Create a multi-service event-driven application with documented event contracts, repeatable local environment, tests and operational runbook.

Capstone · end-to-end implementation
